## 结论

**成功次数/实际运行次数**：上表 1–16 共 16 项均一次通过——其中 #16 是**先发现失败再修复后复验通过**，不计入一次通过；全部为**实际执行**，#18/#19 为静态检查或设计走查，**不与实际执行项合并计算**。

**耗时与成本（有测量）**：

| 项 | 数值 |
| --- | --- |
| 首次全量扫描（113 文件 / 293 MB，含 99 次探测 + 99 张缩略图） | 25.1 s |
| 增量重扫（无变化） | 0.18 s |
| 前端构建 | 0.19–0.57 s，产物 JS 232 KB（gzip 73.5 KB） |
| 检索响应 | 未单独计时（113 条规模下页面无明显等待），**万级耗时为 M4 目标，未测量** |
| 外部 API 费用 | 0（M0 不调用任何 AI 服务） |

**未验证部分及影响**：

- ~~「用系统默认程序打开」的成功分支未触发~~ → 2026-09-27 已补验通过，并因此发现一个真缺陷（F6，见下），不是"用户点一次就好"的问题。
- 音频/音乐播放与 PDF 预览未在真实素材上跑过：`<项目素材>` 里没有音频和 PDF。这两条路径只有类型分支的静态检查。
- missing 的界面呈现未制造真实缺失，只有代码级走查。
- 性能与规模：当前 113 个文件，**万级素材、FTS tombstone 退化、多根目录、跨盘搬家都还没有证据**（分别属 M4 / M1）。
- 打包（M6）、AI 层（M5）完全未开始。

**已发现的缺陷与修订**（均已在本次修复并复验）：

| # | 缺陷 | 现象与证据 | 修订 |
| --- | --- | --- | --- |
| F1 | FTS5 的 `MATCH` 左侧用了表别名 | 检索直接报 `no such column: fts`，五个检索用例全挂 | 改为直接使用表名 `asset_fts MATCH ?`；复验 #4–#7 通过 |
| F2 | 新插入的 `file` 未加入「本次已见」集合 | 首扫时刚入库的文件立刻被标记 `missing`（首次 5 文件试扫出现 `标记缺失: 5`） | 插入后把新 id 加入 `seen`；全量扫描复验 `缺失 0` |
| F3 | `--limit` 局部扫描也做缺失判定 | 抽样扫描会把未处理文件误判为缺失 | 局部扫描跳过缺失判定 |
| F4 | 缩略图 `img` 的 `height:100%` 在 flex 项内退回固有比例 | **看图才发现**：视频卡片的标题被挤出卡片、文字被裁切 | 缩略图改绝对定位 + `object-fit: cover`，行高 168→190；复验 `overflowCards=0` |
| F5 | 媒体标签无法携带自定义请求头 | `<img>`/`<video>` 请求不带 `x-pm-token`，缩略图与视频会 401 | 媒体/缩略图/文本接口同时接受 `?token=` |
| F6 | 「用系统默认程序打开」接口返回 `ok:true` 却什么都没打开（**用户反馈后补验发现**） | 进程级核对：调用后没有任何新进程 | Node 在 Windows 上不给空字符串参数加引号，`cmd /c start "" <路径>` 的空标题消失后 `start` 把路径当成**窗口标题**。改用 `explorer.exe` 走系统关联，并保留一个非空标题的 cmd 兜底 |

**已知限制（不是缺陷，但要记住）**：

- `node:sqlite` 内置 SQLite **3.51.2**，低于 WAL-reset 缺陷的修复版 3.51.3。该缺陷需要**两个连接同时写/checkpoint** 才触发；当前是单进程、单连接、单写者，条件不成立。**M1 若引入多进程写入，必须先升级 SQLite 或改回 better-sqlite3。**
- M0 每个文件对应一个 asset（未做内容去重合并），`hash` 已写入，M1 才能按哈希合并与 relink。
- 库目录**不能**放在 OneDrive / 坚果云 / 网络盘（WAL 需要共享内存）。

**下一步建议**：M1（复制导入 + 哈希去重 + sidecar + relink + 回收站）已在同一批 113 个文件上完成并验证，见 [验证记录-M1](./验证记录-M1.md)。
