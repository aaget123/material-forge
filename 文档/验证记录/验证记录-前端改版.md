## 采用与取舍（为什么不是直接改用那个 Next 工程）

**采用的**：设计令牌（oklch 原值照抄）、布局硬值（侧栏 256px、主区 max-width 1280px + padding 24/32、栅格 gap 16、卡片 4:3 + 内边距 14px、列表行 12×16）、全部中文文案、七类模态分类、卡片信息层级（标题 / 类型·模型徽章 / 日期 / 项目色点+名称）、lucide 图标。

**有意偏离的 5 处**（都有理由，不是省事）：

| 偏离 | 理由 |
| --- | --- |
| 仍用现有 **Vite + 纯 CSS**，没有换成 Next 16 + Tailwind + shadcn | 一个工具链、打包路径（M6 Electron）不变；参考工程的暗色变体是**死代码**（`:root` 无 `.dark` 覆盖，layout 固定 `light`），所以"只做浅色"本身就是忠于原设计 |
| 保留了右侧**详情栏**（参考工程没有） | 本工具需要预览、看图模式、项目/模型编辑、回收站操作；已按浅色令牌重绘 |
| **保留虚拟滚动**（参考工程整栅格直出） | 素材会到万级；卡片行高由列宽 + 4:3 算出，不是写死值 |
| 音频卡片用**真的** `<audio controls preload="none">`，不画程序生成的假波形 | 参考工程的波形是按 id 字符码算出来的装饰，与实际音频无关。画假数据会误导；真实波形等 M2 用 ffmpeg 预算 peaks 再做 |
| 「添加素材」做成**真的能上传**（原始字节 POST，无需 multipart 解析）+ 粘贴文本，并保留"重新扫描 / 导入到库"入口 | 浏览器拿不到任意目录的枚举权限，所以参考工程那套"选文件即入库"必须落到真实上传；同时不能把已有能力藏没 |

**「综合」的含义**：参考工程的 `mixed` 是"一条素材由多种模态组成"。当前映射到内部 `kind='other'`（未归类），真正的"合集/多模态打包"留到 M3。所以综合计数为 0 是真实值，不是坏了。

## 结论

**成功次数/实际运行次数**：#1–#17 共 17 项通过，其中 **#15、#16 是先发现失败、修复后复验通过**，不计入一次通过；#19 为设计走查，不与实际执行项合并计算。

**后端为这次改版新增的能力**：`asset.model` / `asset.excerpt`（含摘要回填命令）、`project.description` / `color` / `modality`、全文索引新增 `model` 列并**启动自愈重建**、`/api/projects`（GET/POST/DELETE）、`/api/assets/:id/project`、`/api/assets/:id/model`、`/api/upload`、`/api/text-asset`、`/api/trash/purge`，以及 CLI `reindex`。

**发现的缺陷与修订**：

| # | 问题 | 证据 | 修订 |
| --- | --- | --- | --- |
| G1 | 顶栏标题被挤成竖排 | 标题框实测仅 **71px** 宽、折成 3 行；`画廊/列表` 也竖排 | 标题块改 `flex:1 1 220px + min-width:0`、标题/副标题 `nowrap + ellipsis`、操作条 `flex:0 0 auto`、顶栏允许换行；复验 628px 单行 |
| G2 | 切换项目/筛选后网格停在旧滚动位置 | 滚到 600px 后切换项目仍停在 600px | 虚拟网格加 `resetKey`，作用域变化即回到顶部；复验 `scrollTop = 0` |

**查证过但不是缺陷的**：我一度以为视频卡片的播放按钮没居中（截图看着偏在右上）。测量后 `play` 中心 (427, 93) 与预览区期望中心 (427, 93) **完全一致**——真实原因是那张卡当时被视口上沿裁切（`preview.y = -5`）。没有据此改动代码。

**未验证部分及影响**：

- **万级素材下的模态计数会偏小**（客户端只统计已加载的 ≤1000 件）。分页 + 服务端模态聚合必须先做，否则计数与筛选在有 10k 素材时会骗人。
- 窄屏（<900px）侧栏直接消失且无替代导航；触摸屏双指缩放未实现。
- 音频没有真实波形（不画假波形是有意的）；「综合」仍是未归类映射，不是真正的多模态合集。
- 上传只测了 0.8MB 的图片；**大文件（>2GB）、断线中断、并发上传未测**（服务端上限 8GB，流式落盘）。
- 项目删除只有接口没有界面入口；项目拖拽归档、批量改项目未做。

**下一步建议**：① 先做分页 + 服务端模态计数（把 #19 这条已知限制消掉，它是唯一会"骗人"的一项）；② 音频真实波形（M2）；③ 「综合」做成真正的合集（M3）。

## 追加修订二：详情栏预览图压住元数据（用户反馈，同日）

**反馈**：「右侧那个信息展示那个图片的展示不是很好，然后就就有可能挡住其他信息」。用户提供的截图里是大图素材（他自己上传的 `<角色F>.png`，4096×4096 / 17.2 MB，模型标为豆包）。

**定位（先测量再改，不猜）**：对素材 #114 量出几何关系——

| 元素 | 实测 |
| --- | --- |
| `.preview` 容器 | top 75 / bottom 339 → 高 **264px** |
| 容器里的 `<img>` | top 47 / bottom 367 → 高 **320px** |
| `.meta-table` 首行 | top **351** |

即图片**上下各溢出 28px**：上面盖住标题区，下面盖住第一行元数据（351 < 367）。

**根因**：`.preview` 是 flex 列容器里的子项、默认 `flex-shrink: 1`。当面板内容总高（75 + 322 + 322 + 113 = 832px）超过可视高（774px）时，flex 把预览区**压缩**到 264px；但里面的 `<img>` 有固定的 `max-height: 320px`，不会跟着缩；又因为 `.preview` 是 `overflow: visible`，于是图片就画到了上下相邻元素上面。

**修订**：
1. `.preview` 改为 `flex: 0 0 auto`（**不参与收缩**）+ 固定高度 `clamp(200px, 30vh, 320px)`；内容超高时由面板**滚动**承担，而不是压缩预览区；
2. 加 `overflow: hidden`，图片在任何情况下都不可能画到邻居上；
3. 图片/视频改成按容器缩放：`max-width/height: 100%` + `object-fit: contain`（宽图自动留黑边，不再靠 320px 魔数）；
4. PDF 的 iframe 高度由写死的 320 改为 100%；
5. 顺手加了 `cursor: zoom-in` 与**点预览图直接进看图模式**（`放大查看` 按钮保留并阻止事件冒泡，避免触发两次）。

**复验（几何证据）**：

| 素材 | 预览区 | 内容 | 上溢 | 下溢 | 是否压住元数据 |
| --- | --- | --- | --- | --- | --- |
| 方形大图 4096×4096（#114 <角色F>） | 75–307（高 232） | img 75–306（232×232） | **0** | **−1** | 否（元数据从 307 开始） |
| 宽图 2752×1376（#14 <角色A>） | 75–307 | img 110–272（324×162，上下留黑边） | −35 | −36 | 否 |
| 文本素材（`<pre>`） | 75–307 | pre 75–306（339×232） | 0 | −1 | 否 |

另外：`overflow` 实测为 `hidden`；宽图那条面板 `scrollHeight 794 > clientHeight 774`，即内容超高时**滚动**而不是覆盖；点预览图 `viewerOpened = 1`、按 Esc 后 = 0。

**证据**：（截图仅本地保留，不入仓库）

### 1. 项目删除（素材进回收站）

侧栏每个项目行悬停即出现 **新建子项目 `+`** 与 **删除项目 🗑** 两个按钮（留在文档流里，不做浮层，避免悬停时布局抖动）。删除前弹确认框，把"东西去哪了"写清楚：

| 场景 | 确认文案（浏览器实测原文） |
| --- | --- |
| 有素材、无子项目 | 将删除项目「短片《<角色A>》」。项目里的 **4** 件素材会**全部移入回收站**，可以随时恢复；磁盘上被引用的原始文件不受影响。 |
| 空项目（bbb） | 将删除项目「bbb」。这个项目里还没有素材，删除后不会产生回收站内容。 |
| 有素材 + 有子项目 | 将删除项目「短片《<角色A>》」，以及它下面的 **1** 个子项目。项目里的 **8** 件素材（含子项目）会全部移入回收站…… |

删除语义按用户补充实现：`deleteProject` 对范围内每个素材调用 `trashAsset`（托管对象移到 `trash/`，**引用型素材只摘索引、磁盘原文件不动**），再删项目行。删除后提示条实测为：`已删除「综合测试子项目」 · 4 件素材移入回收站，可随时恢复`。取消删除后侧栏仍是 `短片《<角色A>》 8 / 综合测试子项目 4 / bbb`，没有任何副作用。

**顺带修掉的三个真问题（都是验证过程中量出来的，不是猜的）**：

| 问题 | 表现 | 根因 | 处理 |
| --- | --- | --- | --- |
| 删除报告低报 | 删 1 父 + 2 子，接口返回 `removed: 1` | `parent_id` 上的 `ON DELETE CASCADE` 先把子项目带走，那条 `DELETE` 自己只删了 1 行，`run().changes` 只数自己删的 | `removed` 改用范围内的 id 数（都是确实消失的行），注释写明原因 |
| 新建项目后被立刻取消选中 | 从 `+` 建子项目后标题栏回到「全部内容」 | 我原先用"列表里找不到就清空选中"的 effect 兜底，而新建那一刻列表还没刷新 | 改成删除时用 `subtreeIds()` 精确判断被删的是不是当前选中项；effect 删除（这条是我自己引入又自己抓到的回归） |
| 清空回收站留下孤儿缩略图 | `verify` 报 `orphanThumbs: 2`，`derived/thumbs` 比库内哈希多 2 个文件 | 缩略图按内容哈希命名，`purgeTrashed` 只删对象与 sidecar | `purgeTrashed` 增加：该哈希在库里已无任何素材时删掉对应缩略图，并在报告里给出 `removedThumbs` |

### 3. 「综合」= 一次加入多种类型

原来的「综合」实际上什么都没做：文件上传的类型是服务端按后缀识别的，选择器只影响粘贴文本，而且一次拖入多种类型时还会被"第一个文件的类型"覆盖掉，所以看起来"填了没用"。

现在「综合」是一个明确的**批量模式**：

- 选中「综合」后**不会**被文件反推类型（拖进来 4 种类型也仍是综合）；
- 一次拖入多种类型时**自动切到综合**；
- 文件列表**追加**而不是替换，每行右侧显示该文件**自动识别到的类型**（`图片/视频/声音/文本/代码/音乐`）；
- 可以**同时**选文件 + 粘贴一段文本，点一次「添加」全部入库；
- 多文件时标题可留空（每件用文件名），按钮写明将要产生几件：`添加（4 件）`。

**实测（真实浏览器 + 真文件）**：用 ffmpeg 现场生成 4 个真实文件（`综合验证图.png` 801 B / `综合验证片.mp4` 5.3 KB / `综合验证音.mp3` 16.6 KB / `综合验证文.txt` 65 B），一次拖入：

| 检查 | 结果 |
| --- | --- |
| 选「综合」前后 | 步骤 0 `图片`（默认）→ 点综合 `综合` → 拖入 4 个文件后仍 `综合`（含 700ms 后复测） |
| 每行类型标签 | `["图片", "视频", "声音", "文本"]` |
| 提交按钮 | `添加（4 件）`，标题为空也可提交 |
| 提示文案 | 「一次加了 4 件：每件用各自的文件名，标题只用于下面粘贴的文本。」「综合 = 一次加入多种类型……（本次已选 4 种类型）」 |
| 实际入库 | 4 件素材全部落到指定项目，标题为 `综合验证文/音/片/图`，各自类型正确 |

### 4. 一个项目里分多个小项目

- 数据层：`project.parent_id`（自引用，`ON DELETE CASCADE`），走 `COLUMN_MIGRATIONS` 增量补列，**不重建库**；
- 树与汇总：`listProjects()` 用递归 CTE 一条 SQL 算出每个项目的 `parentId / count（自己）/ totalCount（含全部后代，去重）/ trashCount / childCount`；
- **选中父项目会连子项目的素材一起列出**（否则"分了小项目"之后父项目看着像空的）——服务端用 `projectScopeIds()` 把项目 id 展开成范围，`searchAssets` 新增 `projects: number[]` 过滤；
- 侧栏渲染成树：`+` 建子项目、`▸/▾` 折叠、缩进上限 2 级（再深不再右推，窄侧栏不被挤没）、父项目计数显示"含子项目"的合计（悬停有明细）；
- 三个下拉框（新建项目的"上级项目"、详情栏与添加素材的"所属项目"）共用同一份树顺序与层级标签（`　└ 子项目`）。

| 检查 | 结果 |
| --- | --- |
| 接口级（临时新库，23 项断言全过） | 建父/子/孙三级；父 `count=0` 而 `totalCount=2`；`childCount` 正确；`/api/assets?project=父` 返回 2 件（两级后代）；`project=孙` 只返回 1 件 |
| 老库升级（用真实 `index.db` 的副本，8 项断言全过） | 备份库**没有** `parent_id` 列（已核对），升级后 2 个项目 `parentId` 均为 `null`，素材 114 条一条不少；副本上建父/子后删父 → `removed=2`，删空项目不产生回收站内容 |
