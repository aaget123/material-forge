# 个人项目管理器 · 开发建议

产出方式：先核实需求与现有实现，再定方案，最后给出可验收的最小样品。
配套证据见 [调研记录](../需求与调研/调研记录.md)。核对日期：2026-09-27。

证据标注沿用指南口径：**✅已验证**（有实现、issue、官方文档或基准）、**⚠️仅宣称**（仅官方/宣传页说法）、**待验证**（尚未运行）。

## 0. 一页结论

| 项 | 结论 |
| --- | --- |
| 做什么 | 一个**本地 Web 应用**（浏览器里用）：素材**复制进统一库**、可搜索、可预览播放、可挂到项目上；AI 能力后置；**跑顺后再打包成桌面应用** |
| 形态（已定） | **先 Web 后打包**：M0–M5 全部在浏览器里开发与验收，M6 用 Electron 套壳成"双击即用" |
| 技术栈 | **Node + TypeScript**：本地 HTTP 服务 + `better-sqlite3` + `sharp` + ffmpeg（复用你 `ai-editor` 的 ffmpeg 与 `资源搜索` 的服务端习惯）+ 浏览器前端。**服务端选 Node 的关键理由：打包阶段 Electron 本身就是 Node，套壳几乎零改造** |
| 不做什么 | 不做本地大模型推理、不做视频转码工厂、不做多用户/同步、不做插件系统、不追 100+ 格式 |
| 库结构 | `library/objects/<hh>/<hh>/<hash>.<ext>` 内容寻址 + 每对象 sidecar JSON + `library/index.db`（**数据库可整库重建**） |
| 本机前提（已核实） | Node v22.22.2 / npm / Python 3.14.4 / git 均就位；ffmpeg 9.0 full build 含 `ffprobe.exe` 可直接复用；**D 盘可用 234.6GB**，库放 D 盘无压力；`rg` 未安装需随包附带 |
| 落地顺序 | M0 真实闭环（扫描→索引→网格→预览→中文搜索）→ M1 托管库与导入可靠性 → M2 统一预览器 → M3 项目层 → M4 搜索增强 → M5 AI 层 → **M6 打包成桌面应用** |
| 第一步（1-2 天） | M0 最小样品：拿 `<内容目录>\<项目素材>`（113 文件 / 293MB）跑通全链路，在**浏览器**里验收，同时验掉 4 个技术假设（见 §8） |
| 最大风险 | 不是功能做不出来，而是**元数据只存在数据库里 + 库靠绝对路径寻址**——Eagle 改名库目录找不到库、Billfish 迁移后标签全丢、Lightroom missing photo 都是这个病（见 §9） |

## 1. 需求结论

### 1.1 你的原话与实测事实

- 原话：「我想将我的素材全都放进项目管理器里面，可以在项目管理器里面随时地查看和打开使用」→ 需求是**统一入口 + 集中存放 + 随手查看/打开**，不是"给现有文件夹加个索引"。
- 勾选的优先级：① 快速找到（全文+标签+筛选）② 统一预览与播放 ③ 素材挂到项目 ④ AI 语义搜索/自动打标/转写。
- AI 取舍：选"先不做 AI，把管理和搜索做扎实"，同时提到可用小米全模态模型 → 结论是**AI 不进首版关键路径，但第一天就留出适配器接口**，且只做云 API 一种实现。
- 实测现状（本机扫描，排除 `.git`）：`<内容目录>` 共 **8781 个文件 / 3.46 GB**，类型覆盖 png/apng/jpg（383MB）、mp4（895MB）、wav+mp3（76MB）、js/py/ts 代码、md/txt/html 文档。
- 现状里混着大量**非素材**：`.exe 1.5GB`、`.map 27MB`、`.pyc`、`.pak`、`.pyi`——这是 node_modules / 打包产物 / 虚拟环境。索引器必须有默认忽略规则，否则第一版就会被噪音淹没。
- 工具链实测：Node **v22.22.2**、npm、Python **3.14.4**、git 均在 PATH；`ffmpeg.exe` / `ffprobe.exe` 位于 `<内容目录>\shipingchuli\ffmpeg-9.0-full_build\bin`（**v9.0 full build**）；`rg`（ripgrep）**未安装**；`ai-editor\.mimo_key` 就位（52 字节）。
- 磁盘实测：C 盘可用 79.1GB，**D 盘可用 234.6GB**，E 盘可用 176.7GB → 库放 D 盘空间充足（现有库仅 3.46GB）。

### 1.2 已确认需求（可直接进入设计）

| 编号 | 需求 | 成功条件（可观察） |
| --- | --- | --- |
| R1 | 素材集中进库 | 导入后素材存在于库目录；原目录文件仍在（复制而非移动） |
| R2 | 随手查看 | 任意素材双击 1 次内出现在统一预览器，不需外部软件 |
| R3 | 打开使用 | 可从预览器用系统默认程序打开；可定位到文件所在路径 |
| R4 | 搜索 | 中文关键词能在标题/路径/笔记/正文中命中；结果 <300ms（万级） |
| R5 | 项目关联 | 素材可加入项目并标记角色；项目视图能看进度与产出清单 |
| R6 | 不丢数据 | 库目录可改名/搬家；数据库删除后能重建出标签与项目关系 |

## 3. 总体方案

### 3.1 两条正交的轴线（这是"项目管理器"与"素材管理器"的区别）

```
                 素材库（内容轴）                      项目（工作轴）
        ┌──────────────────────────┐        ┌──────────────────────────┐
        │ asset（内容唯一）        │        │ project（目标/进度）     │
        │  ├ file（多个物理路径）  │◄──────►│  ├ project_asset(role)   │
        │  ├ tag（层级标签）       │        │  └ 看板 / 清单 / 导出    │
        │  └ collection / 智能集合 │        └──────────────────────────┘
        └──────────────────────────┘
```

- **内容轴**回答"我有什么、在哪、内容是什么"；同一内容只存一份（内容哈希去重），可以有多个物理路径。
- **工作轴**回答"我在做什么、进行到哪、用到哪些素材"；项目里放的是对素材的**引用**，不复制文件。
- 一条素材可以同时属于多个项目和多个集合——这正是 Eagle 用 folder ID 虚挂、以及 `asset_project` 多对多要解决的事。

### 3.2 三层结构（先 Web，后打包）

| 层 | 职责 | 关键约束 |
| --- | --- | --- |
| **core（纯 Node，可 CLI 单跑）** | 扫描、哈希、元数据、缩略图、索引、作业队列、查询 | **不依赖任何 UI 与 HTTP**。可以先在真实素材上验证索引正确性 |
| **server（本地 HTTP 服务）** | 把 core 暴露成 REST/JSON + 媒体流；绑定 `127.0.0.1` | 前端只通过它访问数据；**视频/音频必须支持 HTTP Range**，否则进度条拖不动 |
| **web（浏览器前端）** | 网格/列表、筛选器、统一预览器、项目看板 | 虚拟滚动是硬需求（万级条目）；资源路径必须相对，方便以后被套壳加载 |
| **app（Electron 外壳，M6）** | 窗口、文件对话框、托盘、开机自启、关联文件类型 | **只做系统集成**，不放业务逻辑；理想情况是"启动服务 + 打开窗口" |

`core` 与 `server` 分开的价值：可以先在 CLI 上验证索引正确性再花时间做界面；打包时也只需把 `server` 作为子进程拉起（或并进主进程），前端资源原样复用——**这就是"最后再打包"能便宜的原因**。

## 4. 六个关键技术决策

### D1 · 形态：先做本地 Web 应用，最后用 Electron 打包

- **选择**：M0–M5 做**本地 HTTP 服务 + 浏览器界面**；M6 用 **Electron** 套壳成桌面应用（不做 Tauri）。
- **为什么先 Web**：开发与调试最快（浏览器 DevTools 直接看真实渲染结果），不需要每次改代码都重打包；媒体预览、虚拟滚动这些难点在浏览器里就能验完；你 `shipingchuli\ai-editor` 已经跑通"本地服务 + Web UI"这套模式，无学习成本。
- **为什么打包阶段选 Electron 而不是 Tauri**：✅ Tauri 2 的 WebView2 **播不了 MKV/HEVC**，社区解法是把 libmpv 塞进去（多为 GPL，影响分发许可）；Electron 自带 Chromium，与你浏览器里已经验证过的播放行为**完全一致**——"开发时能播、打包后不能播"这类事故可以直接避免。
- **打包代价**：安装体积约 200MB，常驻内存 200-400MB。个人自用可接受。
- **兜底（实测后降为可选）**：抽样你现有视频 **25/25 为 `h264`**，Chromium 直接可播。仅对 MKV/HEVC/AV1 才需要 ffmpeg 生成**代理片段**，或"用系统默认播放器打开"一键跳转。
- **现在就要守的约束**（否则打包时会返工，详见 §13）：前端资源用相对路径、服务端口可配置、所有数据访问走 HTTP 而不依赖 `file://` 或浏览器专有 API（如 File System Access）。

### D2 · 库模式：托管为主 + 引用为辅 + 内容寻址

- **选择**：导入时默认**复制**进库（原目录保留），库内以内容哈希命名。
- **依据**：你的原话是"全都放进项目管理器里面"→ 托管库。但 ✅ 托管库的典型事故是"库与绝对路径强耦合"（Eagle 官方 FAQ）与"迁移时元数据丢失"（Billfish 论坛原帖）。内容寻址（`objects/ab/cd/<hash>.<ext>`）让库目录可以整体改名/搬家而不破坏引用。
- **例外规则**：单个 >2GB 的文件、以及已在库内目录的文件，默认改为**仅引用**（记录路径），避免双份占盘与无意义的复制等待。
- **绝不**：导入时移动或删除原文件。删除一律先软删除。

### D3 · 数据层：SQLite 单库 + sidecar 双写，数据库可整体重建

- **选择**：`better-sqlite3`（同步 API，单写者天然安全） + WAL + 每个素材旁写 sidecar JSON。
- **依据**：
  - ✅ WAL 下读写不互斥但**同一时刻只有一个 writer**；WAL **不能用于网络盘**（需要共享内存）。
  - ✅ 必须 SQLite **≥3.51.3**：3.7.0–3.51.2 的 WAL-reset bug 在两个连接同时写/checkpoint 时可损坏数据库，2026-03-13 修复。
  - ✅ 备份只能走 `VACUUM INTO` / backup API / `sqlite3_rsync`；直接复制文件必须在无事务时且连 `-wal` 一起复制。
  - ✅ **切勿把库放进 OneDrive / 坚果云 / 网络盘**（锁语义 + 非原子复制）。
- **代价与对策**：把标签、项目关系、笔记、评级**同时写进 sidecar**，数据库删掉能重建；智能集合存**结构化查询 AST（JSON）**而不是 SQL 字符串，否则 schema 一演进全部失效（✅ 该结论来自对 Eagle `metadata.json`、Lightroom 智能集合、PhotoPrism 实体层的对照）。

### D4 · 中文搜索：FTS5 + 应用层 bigram

- **选择**：FTS5 用 `unicode61` 分词 + 额外一列由应用写入**预切 bigram**；同时保留 `LIKE` 前缀补短词。
- **依据**：✅ FTS5 默认 `unicode61` 对中文不切词；`trigram` 有硬坑——**少于 3 个 unicode 字符的子串不匹配任何行**，`LIKE/GLOB` 不含 ≥3 字符非通配串时退化为全表线性扫描，`case_sensitive=1` 时只能 GLOB。个人规模最稳是应用层切 bigram。
- **维护**：✅ FTS5 频繁 REPLACE/UPDATE 会留 tombstone 导致查询退化（实测 70 分钟内 0.13s→0.24s），需调 `automerge/crisismerge` 并定期 `optimize`。用 external-content 表 + 只索引文本列，夜间 optimize。

### D5 · 索引流水线：阶段化 + 可重跑 + 断点恢复

- **选择**：导入/扫描 = 生成作业，作业按阶段推进，每个阶段结果落库、失败可重试、可中断续跑。
- **依据**：✅ Immich/Paperless 的"导入即队列 + 后处理流水线"是混合媒体能规模化检索的前提；✅ `ReadDirectoryChangesW` 异步缓冲区溢出会**丢事件**，所以监听之外必须有周期对账扫描。
- **阶段**：`stat → hash → metadata → thumbnail/waveform/proxy → text-extract → (可选) ai-annotate`。

### D6 · AI 层：适配器 + 云 API（小米 MiMo），后置、异步、有预算

- **选择**：单一 `AiProvider` 接口，首个实现是 MiMo；**不进首扫路径**，只在队列空闲时跑；结果按 `(input_hash, task, model)` 缓存。
- **依据**：✅ MiMo-V2.5 是**原生全模态**（text/image/video/audio 输入，text 输出），1M 上下文，OpenAI 兼容协议（改 `base_url` + `model` 即可迁移），支持结构化输出；定价 **输入 ¥1/M（缓存命中 ¥0.02）、输出 ¥2/M**。→ 图片打标、视频摘要、音频转写、自然语言搜索可以用**同一个 API**，不需要本地 GPU、也不需要第二个模型。
- ⚠️ 注意：**ONNX Runtime DirectML 已被官方降级为 "sustained engineering"**，新功能转向 WinML，且同一 session 只能单线程 Run。→ 任何"本地推理跑 GPU"的方案在 2026 年都不该作为默认路径。
- **成本控制**：全库跑之前先用 100 条真实样本实测（单张图 / 每分钟音频的 token 与费用），设月度预算上限，超限自动停；AI 关闭时库必须完全可用。
- **不做主人**：自动打标/描述只进**候选区**，人工确认（支持批量确认）后才写进正式标签与 sidecar；提供"全库关停 AI"开关。这条克制有明确反例支持（§1.4）。

## 5. 库目录与数据模型

### 5.1 目录布局

```
<库目录>\                          # 可配置；不要放在云同步目录
  index.db                          # SQLite（可删除，可重建）
  index.db-wal / -shm
  objects\
    a3\f9\a3f9c1...e7.jpg           # 内容寻址，扩展名保留
    a3\f9\a3f9c1...e7.jpg.json      # sidecar：标签/项目/笔记/评级/来源
  derived\                          # 全部可重建，不进备份
    thumbs\a3\f9\a3f9c1...e7.webp
    frames\a3\f9\..._sprite.webp    # 视频悬停预览
    peaks\a3\f9\..._peaks.json      # 音频波形（预计算）
    proxies\a3\f9\...mp4            # 播不了的格式才生成
  trash\                            # 软删除，保留 sidecar
  manifests\checksums-YYYYMM.txt    # 校验和清单
  library.json                      # 库根标识（库 ID/版本/迁移记录）
```

关键点：`derived/` 与 `index.db` 都是**缓存**，删掉只损失时间；`objects/` + `library.json` 才是资产本体。

### 5.2 关系要点

- `asset` 1—N `file`：同一内容可能有多个物理路径（库内 + 原目录引用）。
- `asset` N—M `tag`（`tag.parent_id` 支持层级，可继承）。
- `asset` N—M `project`（带 `role` 与排序）。
- `collection`（显式集合，树）与 `smart_collection`（保存的查询 AST）分表。
- `job` 表驱动流水线；`ai_result` 表按 hash 缓存 AI 结果。

## 9. 风险与对策（按"最可能让项目失败"排序）

| 风险 | 为什么会发生 | 对策 |
| --- | --- | --- |
| **元数据只躺在数据库里** | 图省事，标签/项目关系只写 DB | sidecar 双写；sidecar 是真相，DB 是索引；定期"删库重建"演练 |
| **库路径强耦合** | 库内记录绝对路径 | 内容哈希寻址 + 相对路径 + relink（按 hash/size/fileid 自动重链，最后才人工定位） |
| **范围膨胀** | 想一次做完搜索+播放+项目+AI | 严格按 M0→M5；每阶段有验收闭环才能进下一阶段 |
| **打包阶段原生模块翻车** | better-sqlite3/sharp 需匹配 Electron ABI，asar 会挡原生文件 | 风险已后移到 M6；届时 `asarUnpack` + `electron-rebuild`；让服务**以子进程方式**运行（用系统的 node 或打包的 node），可绕开主进程 ABI 问题 |
| **本地服务被别的程序或网页调用** | 本地 HTTP 端口对本机所有进程开放，恶意网页可用 DNS rebinding / CSRF 访问它 | 绑定 `127.0.0.1`（**不是** `0.0.0.0`）+ 随机端口 + 每次启动生成 token（前端放请求头）+ 校验 `Origin`/`Host` + 关闭 CORS |
| **端口冲突 / 服务没起来时页面空白** | 固定端口被占；先开浏览器后开服务 | 端口自动探测并把实际端口写进 `runtime.json`；前端连不上时给明确提示与"启动服务"指引，而不是白屏 |
| **改了代码看不到新版** | 浏览器强缓存前端资源 | 开发期禁缓存；静态资源带内容 hash |
| **中文搜索体验差** | FTS5 默认不切中文 | 应用层 bigram（D4） |
| **索引越用越慢** | 频繁更新产生 FTS tombstone；全量重扫 | 定期 `optimize`；增量扫描 + 监听 + 周期对账（监听会丢事件） |
| **AI 烧钱且不可控** | 全库盲跑 | 100 条样本实测 → 预算上限 → 缓存 → 可随时关闭 |
| **磁盘被库吃两倍** | 复制导入大视频 | >2GB 只引用不复制；`derived/` 可清理并给出占用面板 |
| **整理变成拖延、标签荒废** | ✅ 手动打标在千级素材后必然衰减（V2EX 1104923 直接反馈） | 标签以批量操作为主；AI 只出候选摊薄人工成本；保证每周都有能收尾的整理动作 |
| **素材真的丢了** | 误删、库损坏、迁移事故 | 软删除 + 回收站；校验和清单；restic/kopia 快照；**每季度一次恢复演练**（只备份不演练等于没备份） |

## 10. AI 层落地要点（M5）

1. **接口先定，实现后置**：M0 就写好 `AiProvider` 的空实现与调用点，避免以后改架构。
2. **任务清单**（都走同一个 MiMo API）：
   - 图片：自动打标、生成描述、按内容聚类；
   - 视频：抽帧后做场景摘要、生成可搜索的描述；
   - 音频/音乐：转写（歌词/人声/对白）、风格标签；
   - 文本/代码：摘要、按语义打标签；
   - 自然语言搜索："找上次那个沙滩上的打斗片段" → 生成结构化查询 AST → 本地执行（**模型只产意图，执行端校验参数**，符合指南"确定性执行、模型负责判断"）。
3. **可靠性**：批量任务走 `job` 表；失败重试有上限；结果按 `input_hash` 缓存，模型升级才失效；AI 不可用时全部功能降级为关键词搜索。
4. **成本**：先实测再放量；记录 `tokens_in/tokens_out/cost` 到 `ai_result`，给一个可查的成本面板。
5. **隐私**：素材要出本机。给一个明确的开关与目录白名单（例如 `认证`、`作业` 这类私人目录默认不上传）。
6. **只出候选**：自动标签/描述默认落"候选区"，人工确认后才写进 sidecar 成为正式元数据；提供全库关停开关，并保证失败时降级为关键词搜索而不是报错（§1.4 有证据支持这个克制）。

## 13. 打包路径（M6，后置但接口现在就要留）

### 13.1 为什么"最后打包"是低风险的

因为服务端是 Node：Electron 自带 Node 运行时，打包时**不需要引入任何新语言或运行时**（这正是没选 Python 做服务端的主要原因——Python 方案到最后要把整个解释器和依赖打包进去）。参考做法：

```
Electron 主进程启动
  ├─ fork 出 server 子进程（或用 utilityProcess）→ 监听 127.0.0.1:<随机端口>
  ├─ BrowserWindow 加载 http://127.0.0.1:<端口>   ← 与浏览器版同一份前端资源
  └─ 退出时确保子进程一起退出（避免残留进程占端口）
```

### 13.2 现在（M0 起）就必须守住的 6 条约束

| 约束 | 不遵守的后果 |
| --- | --- |
| 前端资源全部相对路径，不用绝对 URL | 套壳后加载 `file://` 或自定义协议时全部 404 |
| 服务端口可配置且有默认值，不写死 | 端口冲突时无法启动；打包后更难改 |
| 所有数据访问走 HTTP，不用 `file://` 直读磁盘、不用 File System Access API | 打包后权限模型变化，功能直接失效 |
| 不在前端硬编码"用户目录/盘符" | 换机器或换盘后失效 |
| 打开外部程序、读写文件等系统动作一律由**服务端**执行 | 浏览器沙箱里做不了，套壳后权限边界也不同 |
| 服务只依赖 `127.0.0.1`，不依赖系统级安装（不装全局服务、不改注册表） | 打包后无法以普通用户权限运行 |

### 13.3 M6 的实际步骤

1. `npm i -D electron electron-builder`；
2. 写 `app/main.js`：拉起 server 子进程 → 拿端口 → 开窗口 → 关窗时杀子进程；
3. `asarUnpack` 处理 `better-sqlite3`/`sharp` 的原生文件，必要时 `electron-rebuild`；
4. 打一个便携版先自用，确认"媒体播放行为与浏览器版一致"；
5. 再考虑安装器、图标、开机自启（此时才需要真实签名，自用可跳过）。

**验收**：安装包在干净目录下双击可用；库与浏览器版是同一个（不是两套数据）；关窗后进程真的退出。

1. ~~库放哪个盘~~ **已自查，无需你回答**：D 盘可用 234.6GB（E 盘 176.7GB，C 盘 79.1GB）→ 建议 `<库目录>`，与代码分离、非系统盘、**不要放在任何云同步目录里**。唯一要你确认的是：愿不愿意让库固定占一个专门目录（而不是塞在 `<内容目录>` 里面）。
2. **服务怎么启动**：沿用你 `ai-editor` 的 `start-ui.bat` 习惯（双击即起服务 + 自动开浏览器）够不够？还是要开机自启常驻？这决定 Web 形态的日常手感。
3. **是否要打包给别人用**：M6 才做，但现在会影响两个设计——库路径要不要允许自定义、要不要预留安装器与升级路径。只有你自己用就可以省掉签名、自动更新与多语言。

## 附录 A · 数据模型 DDL

草稿，M0 按需裁剪：

```sql
PRAGMA journal_mode=WAL;
PRAGMA synchronous=NORMAL;
PRAGMA busy_timeout=5000;
PRAGMA foreign_keys=ON;

-- 来源根目录：托管主体 + 引用目录
CREATE TABLE source_root (
  id            INTEGER PRIMARY KEY,
  path          TEXT NOT NULL UNIQUE,
  mode          TEXT NOT NULL CHECK (mode IN ('managed','referenced')),
  enabled       INTEGER NOT NULL DEFAULT 1,
  ignore_rules  TEXT,                      -- 每行一条 glob
  last_scan_at  TEXT
);

-- 逻辑素材：内容唯一
CREATE TABLE asset (
  id             INTEGER PRIMARY KEY,
  kind           TEXT NOT NULL,            -- image|video|audio|music|document|code|note|bundle
  title          TEXT,
  ext            TEXT,
  size           INTEGER,
  hash           TEXT,                     -- xxHash3 或 BLAKE3
  hash_algo      TEXT,
  captured_at    TEXT,
  imported_at    TEXT NOT NULL,
  rating         INTEGER,
  note           TEXT,
  meta_json      TEXT,                     -- EXIF / ID3 / ffprobe 结构化结果
  text_excerpt   TEXT,
  deleted_at     TEXT                      -- 软删除
);
CREATE INDEX idx_asset_kind ON asset(kind) WHERE deleted_at IS NULL;
CREATE INDEX idx_asset_hash ON asset(hash);

-- 物理文件：同一素材可有多条（库内 + 引用）
CREATE TABLE file (
  id             INTEGER PRIMARY KEY,
  asset_id       INTEGER NOT NULL REFERENCES asset(id) ON DELETE CASCADE,
  source_root_id INTEGER REFERENCES source_root(id),
  rel_path       TEXT NOT NULL,
  volume_id      TEXT,                     -- 卷序列号，换盘符可识别
  file_id        TEXT,                     -- NTFS FileID，用于 relink
  size           INTEGER NOT NULL,
  mtime          TEXT NOT NULL,
  status         TEXT NOT NULL DEFAULT 'present',  -- present|missing|trashed
  UNIQUE(source_root_id, rel_path)
);
CREATE INDEX idx_file_asset ON file(asset_id);
CREATE INDEX idx_file_relink ON file(size, file_id);

CREATE TABLE tag (
  id        INTEGER PRIMARY KEY,
  name      TEXT NOT NULL,
  parent_id INTEGER REFERENCES tag(id),
  color     TEXT,
  UNIQUE(parent_id, name)
);
CREATE TABLE asset_tag (
  asset_id   INTEGER NOT NULL REFERENCES asset(id) ON DELETE CASCADE,
  tag_id     INTEGER NOT NULL REFERENCES tag(id) ON DELETE CASCADE,
  source     TEXT,                          -- manual|ai|imported|filename
  confidence REAL,
  PRIMARY KEY (asset_id, tag_id)
);

CREATE TABLE project (
  id             INTEGER PRIMARY KEY,
  name           TEXT NOT NULL UNIQUE,
  status         TEXT NOT NULL DEFAULT 'active',
  cover_asset_id INTEGER REFERENCES asset(id),
  started_at     TEXT,
  due_at         TEXT,
  progress       INTEGER,                   -- 0-100
  note           TEXT
);
CREATE TABLE project_asset (
  project_id INTEGER NOT NULL REFERENCES project(id) ON DELETE CASCADE,
  asset_id   INTEGER NOT NULL REFERENCES asset(id) ON DELETE CASCADE,
  role       TEXT,                          -- 封面|素材|参考|成片|废弃
  sort_key   REAL,
  added_at   TEXT NOT NULL,
  PRIMARY KEY (project_id, asset_id)
);

CREATE TABLE collection (
  id        INTEGER PRIMARY KEY,
  name      TEXT NOT NULL,
  parent_id INTEGER REFERENCES collection(id)
);
CREATE TABLE collection_asset (
  collection_id INTEGER NOT NULL REFERENCES collection(id) ON DELETE CASCADE,
  asset_id      INTEGER NOT NULL REFERENCES asset(id) ON DELETE CASCADE,
  sort_key      REAL,
  PRIMARY KEY (collection_id, asset_id)
);

-- 智能集合：存查询 AST，不存 SQL 字符串
CREATE TABLE smart_collection (
  id         INTEGER PRIMARY KEY,
  name       TEXT NOT NULL,
  query_ast  TEXT NOT NULL                  -- JSON
);

-- 索引流水线
CREATE TABLE job (
  id         INTEGER PRIMARY KEY,
  asset_id   INTEGER REFERENCES asset(id) ON DELETE CASCADE,
  stage      TEXT NOT NULL,                 -- stat|hash|metadata|thumb|text|ai
  state      TEXT NOT NULL DEFAULT 'pending', -- pending|running|done|failed
  attempts   INTEGER NOT NULL DEFAULT 0,
  error      TEXT,
  updated_at TEXT NOT NULL
);
CREATE INDEX idx_job_state ON job(state, stage);

-- AI 结果缓存
CREATE TABLE ai_result (
  id         INTEGER PRIMARY KEY,
  asset_id   INTEGER NOT NULL REFERENCES asset(id) ON DELETE CASCADE,
  task       TEXT NOT NULL,                 -- tag|describe|transcribe|summarize
  model      TEXT NOT NULL,
  input_hash TEXT NOT NULL,
  result_json TEXT NOT NULL,
  tokens_in  INTEGER,
  tokens_out INTEGER,
  cost_cny   REAL,
  created_at TEXT NOT NULL,
  UNIQUE(input_hash, task, model)
);

-- 全文检索：external content，只索引文本列
-- 应用层额外写入 bigram 列以支持中文子串匹配
CREATE VIRTUAL TABLE asset_fts USING fts5(
  title, note, path_text, tags_text, ocr_text, transcript, code_text, bigram,
  content='asset', content_rowid='id', tokenize='unicode61'
);
```
