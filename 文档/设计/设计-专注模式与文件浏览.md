## 一、专注模式：七类模态各自的形态

一个统一的浮层（`FocusOverlay`），按模态换主体，**共用的外壳**：顶部一条极简工具条（标题 / 路径 / 计数 / 缩放或时长 / 兜底打开 / 关闭），底部一行快捷键提示，`Esc` 关闭，`←/→` 在同类素材间翻页。

| 模态 | 主体 | 交互（都实测过或用得上的键） | 理由 |
| --- | --- | --- | --- |
| 图片 | 现有看图器（保留） | 滚轮定点缩放 5%–2000%、拖拽、双击适应/100%、旋转、`0` 适应 `1` 实际大小 `R` 旋转 | 已经是可用形态，不动 |
| 视频 | 全屏播放器 + 缩放层 | 空格播放/暂停、`←/→` ±5s、`,`/`.` 逐帧、`↑/↓` 音量、滚轮或 `+/-` 缩放画面、拖拽平移、`0` 适应 `1` 100%、`F` 原生全屏、倍速 0.5–2×、画中画 | 视频"放大看"= 对 `<video>` 做 `transform: scale()` + 平移，不重新编码；逐帧与倍速是审片刚需 |
| 声音 / 音乐 | 大播放器 + **真实波形** | canvas 画 peaks、点击跳转、拖动播放头、空格播放/暂停、`←/→` ±5s、倍速、音量、循环 | 见 §三：波形必须是真的，长音频不能让 PCM 常驻内存 |
| 文本 / 代码 | **代码编辑器** | 行号、语法高亮、括号匹配、搜索替换、折叠、多选光标、`Ctrl+S` 保存、`Ctrl+Z` 撤销、未保存标记、行/字数统计 | 用户明确要"VSCode 那种编辑能力" |
| 综合 / 其他 | 文件检视 | PDF → 整窗内置查看器；压缩包/未知类型 → 元数据表 + **首部字节（hex）预览** + 文本探测（若是文本则给编辑器）；任何类型都有关联的项目/生成模型/标签编辑 | 这些类型没法"播放"，专业做法是把"这是什么文件"讲清楚，并给出唯一有意义的动作 |
| （兜底） | —— | 无法预览的类型才出现「用系统默认程序打开」小图标 | 用户要求去掉面板上的按钮；完全不留给 .zip/.psd/.docx 会变成死路 |

**不做**：不画假波形（沿用 M1 的立场）；不做视频转码；不做多文件并排对比（留到 M3）。

## 二、编辑与保存语义（唯一有数据风险的地方）

编辑一条文本/代码素材时，素材身上可能同时挂着两种文件行（这是本项目的既有设计）：

- **托管副本**：`objects/ab/cd/<hash>.<ext>`，路径由内容哈希推导 → **原地改写会破坏"路径=内容"的契约**；
- **引用原文件**：`<内容目录>\...` 里用户自己的文件 → 本工具承诺过"绝不改动"。

因此保存走这条路径：

```
编辑器内容 ──保存──► 写入临时文件 ──sha256──► 新对象 objects/..（内容寻址，天然去重）
                                   │
                                   ├─ 若仓库里已有同哈希对象：直接复用（不写第二份）
                                   ├─ 新建 file 行指向新对象，asset.hash 更新为新哈希
                                   ├─ 旧对象**不删**，记入 asset.meta_json.versions[]
                                   └─ 全文索引与摘要（excerpt）同步重建
```

- **默认「保存新版本」**：不动磁盘上的原文件，随时能回退到上一版；
- **「写回原文件」**：只在素材存在**引用型**文件行时出现，需二次确认（弹窗写明"将修改你磁盘上的这个文件，本工具没有备份"）；执行顺序是**先写库内新版本、再写原文件**，这样即使写原文件失败，库里的新版也在；
- **版本历史**：`meta_json.versions = [{hash, ext, size, savedAt, note}]`，专注模式工具条上给一个"版本"下拉，可切回旧版本查看（旧对象仍在 `objects/` 里，切回 = 再建一条指向它的 file 行）。
- **明确不做**：不做自动保存（避免"我还没想好就写坏了"）；不做二进制类型的编辑；不给托管对象做原地改写。

## 三、音频真实波形（服务端算 peaks）

依据 [wavesurfer.js 性能文档](https://wavesurfer.xyz/docs/performance/)：Web Audio `decodeAudioData` 会把整段音频解成裸 PCM，**60 分钟立体声可超 500MB**；官方建议长音频用 `<audio>` 元素 + 预计算 peaks，且**每声道 1000–2000 个点就够**。

本项目的做法（不引第三方库、不加新二进制）：

```
ffmpeg -i <object> -vn -ac 1 -ar 8000 -f s16le -        （原始 PCM 从 stdout 读）
  → Node 里按固定桶宽取 min/max → 归一化到 -1..1
  → 缓存 derived/peaks/<hash>.json（内容哈希命名，和缩略图同一套纪律）
  → GET /api/peaks/:id 返回 {durationSec, points: [...]}（缺缓存时按需生成）
```

前端：`<audio preload="metadata">` 负责播放（流式、内存与时长无关），canvas 只负责画 peaks 与播放头，点击/拖动 seek。这样既不画假波形，也不会因为一首 1 小时的音频把标签页撑爆。

## 四、图标化操作与可关闭面板

- **图标用 CSS 画**（按要求，不引入图标字体、不复用 lucide 那几个）：`Icon.tsx` 里每种图标是一个纯 CSS 图形（`border` + `::before/::after` + `transform`），共 10 个：复制路径、移入回收站、恢复、在资源管理器中显示、兜底打开、专注模式、关闭、面板-左、面板-右、编辑。统一 24×24 画布、1.6px 线宽、`currentColor`，与现有 lucide 图标的视觉重量对齐。
- **详情栏操作区**：文字按钮 → 一排图标按钮（第一次用时鼠标悬停出 `title` 与 `aria-label`；键盘可达）。危险动作（移入回收站）沿用"点一次变确认"的两步式，不弹 `window.confirm`。
- **面板开合**：左侧栏的 `sidebar` 状态存 `localStorage`，顶栏一个开关图标 + `Ctrl+B`（沿用主流约定）；**右侧详情栏不再有开关**，显隐完全由「有没有选中素材」决定（`selected` 非空即渲染），取消选中走 `Esc`、面板内 `×`；主区始终 `flex: 1`，面板变化时网格按**实时容器宽度**重排（见验证记录第十八步），窄屏（<900px）默认收起侧栏。
- **自适应**：主区用 `min-width: 0` 防止内容把布局顶宽；虚拟网格按容器宽度重算列数（已有 `VirtualGrid` 的 ResizeObserver 承担）；面板开合有 120ms 过渡但不做动画阻塞。

## 五、文件浏览模式（Miller 列 + 详情表 + 预览）

**为什么是这个形态**：[Column Explorer](https://github.com/n23eos/column_explorer) 把单树的问题讲得最清楚——"到两百个文件夹就不行：展开一个分支把其他都挤出屏幕，折叠就丢失位置"。Miller 列**用横向空间换纵向空间，每层一列**，同时看到"在哪、从哪来、下一步"。

**布局**：`侧栏（可关）| Miller 列 + 详情表（主区）| 预览栏（可关）`

- **顶部**：面包屑（每一层可点，回到任意上级）+ 路径输入框（可直接粘贴路径跳转）+ 排序方式；
- **Miller 列**：每列 = 一层目录。目录行可点开下一列；文件行显示类型图标 + 大小 + 修改时间；当前选中的行高亮，所在路径的祖先列保持可见；列宽可拖；
- **详情表**（同一区域的另一种排布，用户截图那种信息密度）：名称 / 修改日期 / 类型 / 大小 四列，表头点击排序（升/降），支持多选；
- **预览**：复用右侧详情栏——图片/视频/音频/PDF/文本直接在栏内预览，加"导入到库 / 移入回收站 / 在资源管理器中显示 / 复制路径"；
- **忽略规则怎么呈现**（这是本项目的特色，不能藏起来）：被忽略的目录（`node_modules`/`dist`/`.cache`…）**默认折叠但仍可见**，行尾挂一个 `忽略` 标记，点开可以浏览（浏览 ≠ 索引）；这样"为什么这些没进库"是个看得见的事实，而不是黑箱；
- **能做什么 / 不做什么**：能浏览任意本地目录、导入到库（复制，不动原文件）、把库内素材移入回收站、在资源管理器中定位、复制路径。**不做重命名/删除真实文件**——那是资源管理器的活，本工具的承诺是"绝不改动你的原文件"。

**后端**：`GET /api/fs/list?path=`（单层列举：名称/是否目录/大小/mtime/类型/是否在库/是否被忽略规则挡住）+ `GET /api/fs/roots`（盘符与已配置根目录）。安全边界沿用现状：只绑 `127.0.0.1`、每次启动随机 token、校验 Host；任何路径都要求 token。**限制**：不做符号链接逃逸检查（本机个人工具，与资源管理器同级权限），这一点写进验证记录的已知限制。
