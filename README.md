# 素材工坊（material-forge）

本地优先的**个人素材 / 项目管理器**：把散落的图片、视频、音频、文档、代码统一**扫描或上传入库**，用浏览器检索、预览、播放、看图，并把素材挂到项目上。
数据全部留在本机，AI 能力后置（不联网也能完整使用）。

> 界面按参考原型（Next + Tailwind + shadcn，参考原型目录已移除）重做为浅色设计：侧栏（全部内容 / 回收站 / 我的项目）、七类模态筛选、4:3 卡片与列表视图。

## 快速开始

```powershell
cd 项目管理器
npm install
npm run web:build       # 构建前端
npm run serve           # 启动本地服务，默认 http://127.0.0.1:8756
```

数据目录默认 `<库目录>`（可用环境变量 `PM_LIBRARY` 改）：

```
<库目录>\
  index.db                  索引（可删除、可重建）
  objects\ab\cd\<hash>.<ext> 内容寻址的托管对象 + <hash>.json sidecar
  derived\thumbs\<hash>.webp 缩略图缓存（可再生）
  trash\                     回收站
  manifests\                 校验和清单
```

命令行（在 `项目管理器/` 下）：

```powershell
node --no-warnings core/cli.ts scan [目录] [--force]     # 扫描索引
node --no-warnings core/cli.ts import                    # 复制导入 + 哈希去重 + sidecar
node --no-warnings core/cli.ts verify [--hash]           # 索引/对象/sidecar 一致性核对
node --no-warnings core/cli.ts relink                    # 库改名或搬家后重链
node --no-warnings core/cli.ts rebuild                   # 从 sidecar 重建索引
node --no-warnings core/cli.ts trash <id> | restore <id> # 回收站
node --no-warnings core/cli.ts reindex                   # 重建全文索引 + 回填文本摘要
```

给人和 AI 共用的查询入口（只读，所有命令都支持 `--json`）：

```powershell
node --no-warnings tools/pm.ts health                    # 库是否可用
node --no-warnings tools/pm.ts projects --json           # 项目列表
node --no-warnings tools/pm.ts search --kind image --limit 10 --q 关键词 --project 项目名 --json
node --no-warnings tools/pm.ts get <id|sha256:哈希> --json
node --no-warnings tools/pm.ts read <id|sha256:哈希> [--max-bytes 20000]
```

接口清单（15 条，含素材字段说明）可直接取：`GET /api/openapi.json`（不需要 token）。

## 设计要点（为什么这么做）

- **元数据不锁死在数据库里**：每个对象旁边写 sidecar，数据库只是索引；删掉 `index.db` 能凭 sidecar 重建，换工具也不会"从头再来"。
- **内容寻址**：对象路径由内容哈希推导，所以库目录整体改名/搬家后一条 `relink` 就能修好引用。
- **只复制、不移动**：导入与上传都不动原文件；回收站里的"删除"只动库内副本，引用型素材的原文件永不被删。
- **原图不存库、缩略图按内容哈希缓存**：`derived/` 与 `index.db` 都是可再生的缓存。
- **本地服务有边界**：只绑 `127.0.0.1`、每次启动随机 token、校验 Host（防 DNS rebinding）、不发 CORS 头。

## 已知限制

- SQLite 用的是 `node:sqlite` 内置的 3.51.2（低于 WAL-reset 修复版 3.51.3）；当前单进程单写者不触发，**引入多进程写入前必须先升级**。
- **库目录不要放在 OneDrive / 坚果云 / 网络盘**（WAL 需要共享内存，会损坏数据库）。
- 库位于**仓库目录内**（`素材库/`，已 gitignore），是用户为便于管理主动要求搬进来的：它不在备份/搬迁的默认路径上，**动仓库的清理命令（如 `git clean -xfd`）会删掉它**。
- 模态计数与筛选目前是客户端按已加载的 ≤1000 件算的：素材超过 1000 件时计数会偏小（分页 + 服务端聚合尚未做）。
- 「综合」现在是"一次加入多种类型"的批量入口，真正的多模态**合集**（多件素材打包成一条）尚未做。音频波形已实现（服务端算 peaks），不再是缺口。
- 子项目的数据层支持任意深度，界面缩进只到 2 级；"把项目移到别的父项目下"还没有 UI。
- 搬家只在同盘改名上验证过；备份只有校验和清单，**尚未做过真实恢复演练**。
- 文本编辑的版本历史**只保留上一版**（更老的版本连对象一起回收），不能回退到更早的版本。

更完整的限制与"未验证部分"逐条写在各份验证记录里。
